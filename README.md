# Datalix availability monitor

Раз в минуту монитор получает официальный sitemap Datalix, находит все страницы с KVM, dedicated и game-серверами, проверяет каждую товарную карточку и публикует в Telegram только подтвержденные появления в продаже.

Пост содержит название, цену, ключевые характеристики, прямую ссылку заказа и отдельную кнопку для каждого появившегося сервера.

## Что защищает от ложных и повторных постов

- доступность определяется по настоящей ссылке `cp/order/config`, а не только по отсутствию текста `Sold out`;
- по умолчанию явный переход публикуется на первой успешной проверке; при необходимости число подтверждений настраивается через `CONFIRMATIONS_REQUIRED`;
- битая, пустая или неоднозначная карточка не меняет сохраненное состояние;
- первый запуск создает тихий baseline и не публикует весь уже доступный ассортимент;
- состояние и очередь недоставленных Telegram-событий сохраняются атомарно на диске;
- большие пачки автоматически делятся по лимиту Telegram, а доставленные части сразу удаляются из очереди;
- Telegram 429/5xx повторяются с учетом `retry_after`;
- проверки не накладываются друг на друга, HTTP-запросы имеют timeout и retry;
- новые страницы серверов автоматически подхватываются из официального sitemap;
- контейнер работает без root, без capabilities, с read-only filesystem и healthcheck.

## Запуск

1. Создайте бота через `@BotFather`.
2. Добавьте бота администратором канала с правом публикации сообщений.
3. Скопируйте `.env.example` в `.env` и укажите токен и `TELEGRAM_CHAT_ID`. Для публичного канала можно использовать `@channel_name`, для приватного — числовой ID вида `-100...`.
4. Запустите:

```bash
docker compose up -d --build
docker compose logs -f monitor
```

Первый проход будет тихим. При стандартных настройках сервер публикуется на первой минутной проверке после появления активной кнопки заказа.

## Проверка без Telegram

Команда делает живой проход, печатает итог и сохраняет baseline в `./data/state.json`, но ничего не отправляет:

```bash
npm ci
npm run check
```

Если нужна чистая проверка без влияния на production-state:

```bash
STATE_FILE=/tmp/datalix-check-state.json npm run check
```

## Эксплуатация

```bash
docker compose ps
docker compose logs --tail=100 monitor
docker compose restart monitor
```

Не удаляйте каталог `data` при обновлении: без него монитор потеряет baseline. Секрет бота хранится только в локальном `.env`, который исключен из Git и Docker build context.
